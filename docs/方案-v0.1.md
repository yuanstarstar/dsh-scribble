## 0. 一页结论

**要做的事**：给 DSH 一套“用笔画写字和画画”的工具，而不是让它贴一个现成字体、或生成不可复现的 AI 图片。

**核心路线**：

1. **笔画优先**：文字和简笔画都表示成“中心线 + 笔宽 + 风格参数”，而不是一开始就做字体轮廓。
2. **图片先落地**：v1 输出 SVG + PNG，聊天里直接可见，文件可编辑、可归档。
3. **字体后置**：M2 用 `opentype.js` 把拉丁/数字笔画偏移成闭合轮廓，导出可安装 TTF；中文 TTF 不在 v1 承诺范围内。
4. **中文可选**：不把汉字笔画数据打进插件包；用户显式开启后，按需下载 `hanzi-writer-data` 并缓存，遵守 Arphic Public License。
5. **确定性**：同一输入 + 同一 seed → 同一张图；方便测试、复现和“再来一张只换风格”。
6. **风格可学习**：旧画/反馈 → `StyleProfile`；同一套笔画引擎让“画的风格”和“字的风格”互相迁移。见[增补方案](风格训练与反馈-方案-v0.1.md)。

**推荐的首版范围（M1）**：

- `scribble_write`：ASCII 字母、数字、常用标点的手写风图片（SVG/PNG）；含汉字时按字下载笔画数据并渲染。
- `scribble_draw`：10 个左右的参数化简笔画模板 + 自由笔画。
- `scribble_font`：字体预设列表、字样表；TTF 导出放到 M2。
- 中文：按字下载并缓存笔画数据（已实现 0.2.0）；字形是标准楷体，不是用户的手写字形。
- UI：先不做；工具可用后再加“手稿本”画廊（M3）。
- 风格训练：M1 之后做 S1（旧画捕获）+ S2（反馈学习）；不阻塞首版。

**本方案需要你拍板的四件事**见 [§14](#14-需要你拍板的四件事)。

## 1. 需求拆解

“让 DSH 写出自己的字体和简笔画”可以拆成三种不同深度的能力，成本差很多：

| 理解 | 交付形态 | 成本 | 建议 |
|---|---|---|---|
| A. 手写风文字图片 | PNG/SVG，聊天里能看 | 低 | **v1 必做** |
| B. 可安装的字体文件 | `.ttf`/`.otf`，装进 Word/浏览器 | 中 | **M2 做拉丁/数字** |
| C. 完整中文个人字体 | 几千到几万字的 TTF | 高，且许可证复杂 | 不在首版承诺 |
| D. AI 生成任意简笔画 | 模型出图 | 高、不可复现、不可编辑 | 不做；本方案是“程序化简笔画” |

**“自己的字体”在本方案中的定义**：

- 不是复制某款现成字体，而是用一套**自有的骨架字形 + 风格引擎**生成文字；
- 风格可调：倾斜、抖动、压感、基线跳动、墨水质感、纸张；
- 同一段文字可以用不同 seed 生成不同“手气”，但都能复现；
- 需要时，能把拉丁/数字骨架编译成 TTF，装进系统字体列表。

**“简笔画”在本方案中的定义**：

- 不是 AI 生图，而是**参数化线稿**：火柴人、猫狗、房子、树、太阳、云、花、爱心、箭头、对话泡等；
- 每个模板有参数（姿态、朝向、表情、大小、配件），模型只需填参数；
- 也允许模型直接给自由笔画（点列），用于模板覆盖不到的东西；
- 输出 SVG（可编辑）和 PNG（可直接看）。

**非目标（v1 明确不做）**：

- 不做中文全字库 TTF；
- 不做字体训练/少样本字体生成（MXFont、DG-Font 等）；
- 不做云端生图、不调用外部绘图 API；
- 不做“任意 SVG 导入后编辑”的完整矢量编辑器；
- 不保证生成的每个字形都达到商业字库的排版质量。

## 2. 网上调研

### 2.1 单线/骨架字体：最适合“手写”和“简笔画”的底座

普通 TTF 是**轮廓字体**（闭合填充），而手写、简笔画、笔画动画需要的是**单线中心线**（single-line / monoline / skeleton）。这两类数据的差别，决定了整个技术路线。

主要参考：

- [p5-single-line-font-resources](https://github.com/golanlevin/p5-single-line-font-resources)：整理了 150+ 单线字体资源，包括 Hershey、Relief、ISO 3098、M+ Stroke、LingDong 的 chinese-hershey-font、`ttf2hershey` 等。作者特别提醒：单线 TTF 很罕见，普通软件渲染单线字体会不正常，通常要用 `opentype.js` 之类的库自己解析。
- [Hershey fonts](https://github.com/techninja/hersheytextjs)：1967 年的经典单线字形，原始字形为公有领域，覆盖 1377 个字符；npm 包 `hersheytext` 2.0.0 是 MIT，但依赖 `cheerio`，运行时偏重。
- **M+ Stroke**：约 5200 个 CJK 单线字形，但来自 GPLv2 项目，**不直接打包进本插件**。
- **chinese-hershey-font**：中文单线字形的另一来源，许可证需逐项核对，暂列备选。

**结论**：

- 拉丁/数字/标点的骨架，优先用**公有领域 Hershey** 作为兜底覆盖，再叠加自研风格层；也可以内置一套自研骨架（先覆盖 A–Z、0–9），用于更有辨识度的展示字。
- 不在运行时依赖 `hersheytext`；构建期把需要的字形数据抽成紧凑 JSON，随插件以公有领域数据分发，并附 NOTICE。
- 单线数据天然适合简笔画：同一条“折线 + 笔宽”管线既能写字也能画火柴人。

### 2.2 字体编译：`opentype.js` 能写 TTF，但难点在“描边转轮廓”

- [opentype.js](https://github.com/opentypejs/opentype.js) 2.0.0，MIT，unpacked 约 3.6 MB；支持解析 TTF/OTF/WOFF，也能用 `Path` 构造字形并写出 TTF。
- 它适合做：
  - 读取/校验我们生成的 TTF（glyph 数、cmap、advance、名称表）；
  - 把“中心线 + 笔宽”偏移成闭合轮廓，再组装 `Font`。
- **真正的难点不是 API，而是轮廓质量**：
  - 中心线偏移后会产生自交、尖角、重叠；
  - TTF 使用非零环绕填充，重叠轮廓方向不一致会出现“空洞”；
  - 需要做轮廓 union / 清理，候选库是 MIT 的 `clipper-lib`（需在 M2 做 spike 验证）；
  - 如果 union 质量不达标，退路是：先只导出简单字形，或保留 SVG 单线字体作为内部格式，不承诺 TTF。

**结论**：TTF 导出放 M2，先做技术 spike，不作为 M1 的验收项。

### 2.3 中文笔画数据：能力很强，但许可证必须隔离

- [Make Me a Hanzi](https://github.com/skishore/makemeahanzi)：9000+ 简繁汉字；`graphics.txt` 每个字包含按笔顺的 SVG 轮廓路径和 `medians` 中心线。
  - 坐标是 1024×1024：左上 `(0,900)`、右下 `(1024,-124)`，y 向下递减；
  - 常见变换：`scale(1,-1) translate(0,-900)`；
  - 数据来自 Arphic PL KaitiM GB/UKai，按 **Arphic Public License** 分发。
- [hanzi-writer-data](https://github.com/chanind/hanzi-writer-data)：2.0.1，9585 个文件，unpacked 约 32 MB；每个字一个 JSON：
  - `strokes`：按笔顺的闭合 SVG 轮廓（M/Q/C/L/Z）；
  - `medians`：每笔中心线折线；
  - `radStrokes`：部首笔画索引；
  - 可按字从 CDN 加载，例如 `https://cdn.jsdelivr.net/npm/hanzi-writer-data@latest/我.json`。
- **Arphic Public License 的关键约束**（已核对原文）：
  - “Font”包括修改、转换格式、改名的衍生字体；
  - 原样复制分发必须保留 `ARPHICPL.TXT`；
  - 修改后分发，必须在每个修改文件里写明显声明（何时、如何修改），并让修改整体以同一许可证对第三方 Freely Available；
  - 若字体交互运行，启动时须显示版权、无担保、可再分发声明；
  - 衍生字体本身必须继续用 APL，不能附加额外限制。
- [LXGW WenKai / 霞鹜文楷](https://github.com/lxgw/LxgwWenKai)：OFL 1.1，基于 Fontworks Klee One；可嵌入、捆绑、再分发，但须附 `OFL.txt`；修改衍生字体也须 OFL 1.1；保留名称“霞鹜 / 落霞孤鹜 / LXGW”未经书面授权不能用；禁止单独售卖字体文件；不得与 GPL/IPA 等许可字体混入同一字体文件。

**结论**：

- 中文笔画数据**不随插件打包**；用户显式开启“中文手写”后，按需下载并缓存到用户目录。
- 插件内附 APL 原文、来源说明和“如何关闭/清除缓存”。
- 如果未来要分发由这些数据生成的中文 TTF，衍生字体必须整体 APL；这会限制商用，需单独评估。
- LXGW WenKai 只作为“兜底显示字体”的备选；若捆绑，必须改名、附 OFL、避开保留名。

### 2.4 手绘风：rough.js 可参考，但文字仍要自己做

- [rough.js](https://github.com/rough-stuff/rough)：MIT，手绘风矩形/圆/线/填充；Excalidraw 一类白板工具的手绘感来源之一。
- 它解决的是“几何图形的手绘化”，不解决“字形骨架 + 排版 + 字体导出”。
- 本方案可以借鉴它的**双线抖动、填充排线**思路，但核心笔画引擎自研，避免为一个轻量能力引入额外依赖。

### 2.5 简笔画素材：Quick, Draw! 可参考，不直接打包

- [Quick, Draw! dataset](https://github.com/googlecreativelab/quickdraw-dataset)：5000 万张、345 类，CC BY 4.0。
- raw ndjson 的 `drawing` 是 `[[x...],[y...],[t...]]`，每笔三个数组；simplified 版是 256×256、左上对齐、1px 重采样、RDP epsilon=2.0。
- 这些数据适合做“人类简笔画长什么样”的参考，或训练 SketchRNN；但直接打包需要 CC BY 署名，且风格不可控。

**结论**：v1 的模板全部自研参数化；Quick Draw 只作为设计参考，不进入安装包。

### 2.6 调研结论表

| 需求 | 现成方案 | 决定 | 理由 |
|---|---|---|---|
| 拉丁单线字形 | Hershey / Relief / ISO 3098 | **采用 Hershey 公有领域 + 自研风格层** | 覆盖全、许可证干净、单线适合手写 |
| 中文单线字形 | Make Me a Hanzi / hanzi-writer-data | **opt-in 按需下载** | 能力强，但 APL 约束重，不能无声明打包 |
| 中文字体兜底 | LXGW WenKai（OFL） | 备选，不默认捆绑 | 体积大；捆绑需改名/附 OFL |
| TTF 编译 | opentype.js | **M2 采用** | 可直接写 TTF，也能读回校验 |
| 轮廓 union | clipper-lib | M2 spike | MIT，候选；未验证前不承诺 |
| 手绘抖动 | rough.js | 参考算法，不强制依赖 | 轻量自研更可控 |
| 简笔画素材 | Quick Draw | 参考，不打包 | CC BY；风格不可控 |
| 字体生成模型 | MXFont / DG-Font | v1 不做 | 模型重、非确定、体积大 |

## 3. 关键技术判断

1. **笔画优先，轮廓后置。**
   笔画数据小、可编辑、可做笔画动画、可逐笔加风格；轮廓只在导出 TTF 时生成。反过来（先做轮廓再抽骨架）会丢信息，且难以做手写抖动。

2. **纯 JavaScript 渲染，不引入原生依赖。**
   PoC 已经用 `pngjs` + 自写光栅器跑通；1500×950、2× 超采样约 310 ms。避免 `sharp`/`canvas`/`resvg` 带来的安装失败和平台差异。

3. **确定性和可复现是硬要求。**
   所有随机都走 seeded PRNG（PoC 用 mulberry32）；同一输入、同一 seed、同一版本 → 像素级一致。这样测试可以断言哈希，用户也可以“复制这一张的 seed 再微调”。

4. **数据和代码的许可证分开。**
   插件代码 MIT；Hershey 数据公有领域；中文数据 APL、不打包；LXGW OFL、如捆绑则单独附许可。安装包里不放任何“来源不明”的字体。

5. **工具优先，UI 后置。**
   核心价值是模型能调用 `scribble_write` / `scribble_draw` 产出图片；UI 只是画廊和设置，不应成为 v1 的阻塞项。

6. **聊天里必须看得见。**
   参考 `kkj-luna-dsh-image-bridge` 的做法：`attachments.saveImage()` 拿 attachment ref，`output.render` 返回 text + image block；模型路由不支持图片时，退化为“文字 + 文件路径”。

## 5. 数据模型

### 5.1 笔画与字形

```ts
type Point = [number, number]; // 逻辑像素，y 向下

interface Stroke {
  points: Point[];
  width: number | number[];    // 单值或逐点笔宽
  color?: string;              // #rrggbb
  alpha?: number;              // 0..1
  cap?: 'round' | 'flat';
}

interface Glyph {
  ch: string;
  advance: number;             // em 单位，例如 0.72
  strokes: Stroke[];           // 归一化坐标：x/y ∈ [0,1] 左右
  bbox?: [number, number, number, number];
}

interface FontSpec {
  id: string;                  // 例如 'scribble'
  name: string;                // 展示名
  upm: number;                 // 1000
  ascender: number;
  descender: number;
  glyphs: Record<string, Glyph>;
}
```

### 5.2 风格参数

```ts
interface Style {
  preset: 'clean' | 'pencil' | 'brush' | 'child' | 'ink';
  slant: number;        // 0..0.15，右倾
  jitter: number;       // 0..3 px，线条抖动
  pressure: number;     // 0..1，笔宽随速度/方向变化
  baseline: number;     // 0..0.02，基线跳动
  roughness: number;    // 0.4–2.5，纸面/墨水质感与线条毛糙度
  ink: string;          // #24324a
  paper: string;        // #f6f1e7
  seed: number;
}
```

```json
    { "type": "text", "text": "DSH", "x": 104, "y": 118, "size": 188, "style": "brush" }
  ]
}
```

**坐标约定**：

- 逻辑像素，左上角 `(0,0)`，y 向下；
- 字形归一化坐标 `y=0` 是字顶，`y=1` 是基线；
- TTF 导出时再转换到 `upm=1000`、y 向上的字体坐标系。

### 6.6 统一返回与错误

**成功**：

```json

```

**失败**：

```json

  "ok": false,
  "code": "INVALID_PARAM",
  "message": "template 'dragon' not found",
```

- 参数错误、模板不存在、画布超限、字体缺字、网络失败都返回可读错误 + 修复建议；

- 无论是否附图，PNG/SVG 都落盘，路径可复制。

## 7. 渲染与字体技术

### 7.1 排版

- 每个字形有 `advance`（em 单位）；字距 = `advance * size + tracking`；
- 支持多行：按 `\n` 分行，行高 = `size * 1.35`；
- 对齐：按最长行测量，再偏移；
- 测量不依赖 DOM：直接用 glyph advance 和 bbox，保证 Node 侧可算。

### 7.2 风格引擎

按顺序应用：

1. **骨架采样**：直线/二次/三次贝塞尔 → 等距点列；
2. **倾斜**：`x += (1 - y) * slant`（顶部右移，基线不动）；
3. **抖动**：沿法线加平滑噪声（不是每点独立白噪声，否则像锯齿）；
4. **压感**：笔宽沿笔画做 `sin` 包络 + 方向相关调制；
5. **基线跳动**：每个字一个小的 y 偏移；
6. **墨水质感**：端点加墨点、边缘透明度扰动、纸张颗粒；
7. **颜色/透明度**：支持叠墨变深。

所有随机量由 `seed` 驱动；同一 seed 重跑，PNG 字节一致（PoC 已验证 SHA-256 相同）。

### 7.3 SVG

- 每条笔画输出 `<path d="M... L...">`，`fill="none"`、`stroke-linecap="round"`；
- 变宽笔画在 SVG 里用平均宽度近似（PNG 保留逐点笔宽）；如需完全一致，可输出逐段 `<line>`；
- 填充图元（太阳、树冠）用 `<circle>`/`<path fill>`；
- 带 `<title>` 和生成参数注释，方便归档；
- 不依赖外部字体，SVG 在任何浏览器/Inkscape 里都能打开。

### 7.4 PNG 光栅化

PoC 的做法（已验证）：

- 逻辑画布 1500×950，2× 超采样（3000×1900）；
- 每个线段画“锥形胶囊”：按点到线段距离 + 插值半径算覆盖率；
- 先画图形，再叠加纸纹/暗角，最后 2×2 降采样；
- `pngjs` 编码；PoC 输出 2.59 MB，耗时约 **310 ms**；
- 目标：1500×950 < 1.5 s，4K < 6 s；超大画布直接拒绝。

### 7.5 TTF 导出（M2）

流程：

```
Glyph.strokes
  → 每条中心线按笔宽偏移出左右轮廓
  → 端点加圆帽/平帽
  → 轮廓 union（候选 clipper-lib）
  → 统一环绕方向，去掉自交
  → opentype.js Path / Font
  → 写 TTF
  → opentype.js 读回校验（glyph 数、cmap、advance）
```

**验收口径**：

- `opentype.js` 能读回；
- Chrome 的 `@font-face` 预览正常；
- 字体在 Word/系统字体列表里能显示（至少拉丁/数字）；
- 小字号不发虚、不断线（不要求 hinting）；
- 如果 union 质量不达标，M2 只交付“实验性 TTF”，并在 README 标明限制。

**明确不承诺**：

- 中文 TTF；
- 复杂连字/可变字体；
- 商业字库级排版质量。

### 7.6 中文路径（opt-in）

1. 文本里出现汉字时，自动按字加载；
2. 首次使用某个字时，从 `hanzi-writer-data@2.0.1` 拉取 `<码点hex>.json`；
3. 缓存到 `~/.dsh/scribble/hanzi/2.0.1/`，附来源 URL、时间、许可证提示；
4. 默认 `cjkStyle:"line"`：用 `medians` 中心线，等宽圆头，不做楷体锋顿；需要轮廓时传 `cjkStyle:"outline"`，才用 `strokes` 的闭合轮廓填充（`M/L/Q/C/Z` 解析成多边形）；
5. 数据坐标是 y 向上；直接 `x/1024, y/1024` 映射到 em，不要套 Make Me a Hanzi 的 `scale(1,-1) translate(0,-900)`；
6. 中文单线的粗细由统一 `weight` 决定；画像只影响倾斜（中文缩放 0.25）、抖动（缩放 0.55）、字距，不改字形；
7. 默认不联网；只有含汉字时才下载；缓存可手动删除。

**许可证动作**：

- 插件包内不包含任何汉字数据文件；
- 首次开启时展示 APL 摘要和原文链接，用户确认后再下载；
- 生成图片时在元数据/README 里保留来源说明；
- 如果未来导出中文 TTF，衍生字体整体按 APL 分发，并单独提示用户。

## 8. 简笔画 DSL 与模板

### 8.1 图元

| 图元 | 参数 | 说明 |
|---|---|---|
| `line` | `x1,y1,x2,y2,width,color` | 直线 |
| `path` | `points,width,closed` | 折线/多边形 |
| `curve` | `points`（贝塞尔控制点） | 曲线 |
| `circle` | `cx,cy,r,fill?,stroke?` | 圆 |
| `ellipse` | `cx,cy,rx,ry` | 椭圆 |
| `rect` | `x,y,w,h,fill?` | 矩形 |
| `text` | `text,x,y,size,style` | 题词 |
| `group` | `transform,children` | 平移/缩放/旋转 |
| `template` | `name,params,transform` | 嵌套模板 |

### 8.2 模板契约

```js
export default {
  id: 'stick_figure',
  title: '火柴人',
  params: {
    x: { type: 'number', default: 750 },
    y: { type: 'number', default: 760, description: '脚底基线' },
    pose: { type: 'enum', values: ['stand', 'wave', 'run', 'sit', 'point'], default: 'wave' },
    mood: { type: 'enum', values: ['happy', 'sad', 'surprised', 'neutral'], default: 'happy' },
    hair: { type: 'number', min: 0, max: 8, default: 5 },
    scale: { type: 'number', min: 0.3, max: 2.5, default: 1 }
  },
  draw(ctx, p) {
    const { x, y, pose, mood, hair, scale } = p;
    // 关节坐标、手臂角度、腿角度都由 pose 决定
    // ctx.stroke(points, width, color, alpha)
    // ctx.circle(cx, cy, r, { fill })
    // ctx.text('HI', x, y, size)
  }
};
```

- 模板是代码，不是用户可执行的脚本；场景 JSON 只传参数，不 `eval`；
- 参数校验失败时返回 `INVALID_PARAM` + schema 摘要；
- 模板内部坐标相对 `(x,y)`，`scale` 统一缩放；
- 模板可嵌套（例如 `scene_park` 里放树、太阳、人）。

### 8.3 首版模板清单（10 个）

| id | 说明 | 主要参数 |
|---|---|---|
| `stick_figure` | 火柴人 | pose, mood, hair, scale |
| `cat` | 猫 | pose（坐/走/趴）, tail, whiskers |
| `dog` | 狗 | pose, ears, tail |
| `bird` | 鸟 | flying/perched, wing |
| `house` | 房子 | roof, door, windows, chimney |
| `tree` | 树 | apples, leaves, lean |
| `sun_cloud` | 太阳/云 | rays, cloudCount |
| `flower` | 花 | petals, stem, leaves |
| `heart_star_arrow` | 爱心/星/箭头 | kind, size |

可选第 11 个：`scene_park`（组合场景），用于一键出“树 + 太阳 + 人 + 草地”的完整画面。

### 8.4 自由笔画

- 模型可以直接给点列，适合模板覆盖不到的东西；
- 限制：最多 5000 条笔画、20 万个点、画布最大 4096×4096；
- 点列会做去重、简化（RDP，epsilon=0.5）和越界裁剪；
- 自由笔画同样走风格引擎（抖动/压感可关）。

- 0.3.2 增加 `cjkStyle:"line"`（默认）：用 `medians` 画等宽圆头单线，不做起笔/收笔的锋顿；`outline` 保留楷体轮廓。

**验收（已通过）**：

- 中文 `你好 DSH` 57 帧、70ms/帧：第 5 帧只有“你”的第一笔一段，第 10 帧“亻”刚成形，第 20 帧“好”的第一笔正在画；证明是沿笔画长度推进，不是逐字跳；

- 猫模板 69 帧：逐条轮廓线生长，不是整只猫淡入；
- 中文出图可读，且笔迹明显歪扭；猫模板有手绘抖动，不是印刷直线。

## 11. 总验收清单

实现完成后，用下面 18 条验收：

1. `plugin_manager install_bundle` 能装上，DSH 重启后工具出现；
2. `scribble_write` 返回 PNG，聊天里显示图片，同时给出真实存在的文件路径；
3. ASCII 字母、数字、常用标点无缺字；缺字时有清晰提示；
4. 4 个风格预设肉眼可区分；
5. `scribble_draw` 的 10 个模板都能出图，参数错误返回 schema 提示；
6. 自由笔画能画出一条自定义曲线；
7. 同一 seed 的 PNG 哈希一致；不同 seed 明显不同；
8. SVG 在 Chrome/Inkscape 打开正常，PNG 尺寸与声明一致；
9. 默认无网络请求；中文开启后才有下载；
10. 中文缓存带来源、时间、APL 说明；“清除缓存”有效；
11. TTF（M2）能被 `opentype.js` 读回，Chrome 字体预览正常；
12. 非法路径/超大字串/超多笔画被拒绝，不写配置目录与工作区之外的任意路径；
13. 1500×950 渲染 < 1.5 s，4K < 6 s；
14. 卸载插件后 DSH 正常，生成的文件仍归用户所有；README 含许可证与限制说明。
15. 从任意一张有矢量记录的旧画 `capture`，新文字在 slant/weight/jitter 上肉眼一致，回执含 `profileId` 与置信度摘要；
16. 5 次“太工整”类反馈后，下一次生成的抖动可量化增加；A/B 10 轮后偏好排序与用户选择一致率 ≥ 70%；
17. `reset` 回到预设；`export`/`import` 往返不丢字段；同一 profile + 同一 seed 的 PNG 哈希一致；
18. 风格训练全本地、无网络请求；不训练大模型、不引入原生 ML 依赖，推理纯 JS。

## 12. 风险与对策

| 风险 | 概率/影响 | 对策 |
|---|---|---|
| TTF 轮廓 union 质量差，出现空洞/断线 | 中/高 | M2 先 spike；用 clipper-lib；不达标就降级为“实验性 TTF”，M1 不承诺 |
| 中文字体许可证（APL）合规 | 高/法律 | 不打包数据；opt-in 下载；附 APL 原文；导出中文 TTF 单独评估 |
| 字形质量不够“好看” | 高/中 | 字样表先行；风格预设可调；Hershey 兜底；收集用户反馈迭代 |
| 纯 JS 光栅化性能不足 | 中/中 | bbox 裁剪、typed array、缓存 glyph、限制画布/笔画数；PoC 已 310 ms |
| 引入原生依赖导致安装失败 | 低/高 | 坚持纯 JS；pngjs 已是纯 JS；不引入 sharp/canvas |
| Client UI HMR/打包问题 | 中/中 | UI 后置；先保证 Host 工具；用 `pnpm run dev:web` 验证 |
| 文件路径穿越/覆盖用户文件 | 低/高 | 只允许配置目录下的安全文件名；拒绝 `..`、绝对路径、保留名 |
| 范围膨胀（中文 TTF、AI 生图） | 高/中 | 本方案明确非目标；里程碑拆分；M2 再评估 |
| CDN 不可用/数据变更 | 中/中 | 本地缓存；镜像 URL 可配置；固定版本号；失败时给离线包指引 |
| 同 seed 仍因浮点差异不一致 | 低/中 | 固定 Node/算法；PNG 哈希测试；必要时量化坐标 |
| 风格训练过拟合/一次负反馈塌缩 | 中/中 | 向预设收缩、置信度低时少改、10% 探索、支持 reset/多 profile；见增补方案 |
| 用户把“风格”误当“字形” | 中/中 | 文档/UI 明说；要真正像自己字走 S3 样张；中文不做逐字训练 |

## 14. 需要你拍板的四件事

### ① 首版范围

- **A（推荐）**：拉丁/数字/标点手写图片 + 10 个简笔画模板 + 自由笔画；中文 opt-in；TTF 放 M2。
- **B**：先做中文手写（依赖数据下载），拉丁和简笔画后置。
- **C**：先做 TTF，图片后置。

> 推荐 A：最快形成“能看、能用、能复现”的闭环，风险最低。

### ② 中文策略

- **A（推荐）**：默认关闭；用户开启后按字下载 `hanzi-writer-data`，本地缓存，附 APL 声明。
- **B**：v1 完全不支持中文，只做拉丁/数字。
- **C**：捆绑 LXGW WenKai 做兜底显示（OFL，需改名/附许可，体积大）。

> 推荐 A：能力保留，许可证风险隔离，安装包不变大。

### ③ UI 优先级

- **A（推荐）**：先工具，M3 再做“手稿本”画廊。
- **B**：M1 就做画廊，工具和 UI 一起交付。

> 推荐 A：Host 侧先稳定，避免 Client 打包/HMR 拖慢核心。

### ④ 风格训练深度

- **A（推荐）**：S1 旧画捕获 + S2 反馈学习；不训练大模型，1 张旧画就能演示，10 次反馈能“学会偏好”。
- **B**：在 A 之上加 S3 字形样张（打印 A–Z/0–9，拍照/扫描，逐字变形，仅拉丁）；用户要多花 20–30 分钟写字。
- **C**：神经字体生成（DG-Font/MXFont 一类）；不做，模型重、非确定、本地部署难。

> 推荐 A：先把“记得我的风格”做成闭环；S3 等 M2 的 TTF 稳定后再评估。

```bash
node poc/render-demo.cjs
```
